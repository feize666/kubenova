# Console UI Baseline Audit

Date: 2026-09-16. Read-only product audit; only this report is changed. Paths below are relative to the repository. Browser baseline and integration belong to the parent task. No screenshot claims are made here.

## Prioritized Findings

1. **P1 / code-confirmed: unavailable overview data becomes a success state.** `frontend/src/app/page.tsx:592` defaults missing alert/workload/cluster values to zero and resolves the risk level to success. The label at line 826 and command center at `frontend/src/components/overview/overview-command-center.tsx:9` consequently present a stable state even when metrics are unavailable. Introduce an explicit unknown/degraded state before risk evaluation; metric provenance must affect the aggregate status. Validate cold loading, request failure, partial scope failure, and actual zero-alert success separately.

2. **P1 / code-confirmed: overview bars encode arbitrary percentages.** `frontend/src/app/page.tsx:931` through the cluster bars at line 1007 multiply counts by constants (12, 8, 5, 10, 2, 20). `BarRow` at line 372 clamps the result to 100. Eight critical alerts can appear larger than ten warning alerts; sufficiently large counts are visually indistinguishable. Replace with ratios sharing a meaningful denominator within each metric family, or render count-only values where no denominator exists. Test zero, unknown, small, and large counts. The upward indicators at lines 922 and 957 also indicate a positive count, not a measured change; remove trend symbolism absent a historical baseline.

3. **P2 / code-confirmed: trend chart erases missing intervals.** `frontend/src/app/page.tsx:165` filters out null samples before calculating equal x-axis spacing at line 183. It draws a continuous polyline across the surviving samples. Missing collection periods appear as healthy continuous coverage, and irregular timestamps get equally spaced. Use timestamp-based x positions and split line segments at unavailable samples. Validate a missing middle sample, irregular collection times, single point, and all-null data.

4. **P2 / code-confirmed: sidebar cannot implement the accepted collapse interaction.** `frontend/src/components/shell-layout.tsx:226` and `frontend/src/components/cluster-workspace-shell.tsx:200` supply fixed Sider widths without controlled collapsed state or a desktop collapse trigger. `frontend/src/app/globals.css:15306` additionally forces all four width properties to 248px with `!important`. Adding an Ant Design collapse prop alone will not work. Introduce one shared expanded/collapsed width contract and persisted state, remove conflicting width overrides, and animate only the controlled width with reduced-motion handling. Validate both shells, submenu focus, long cluster names, and 1024px/mobile navigation.

5. **P2 / code-confirmed callback ordering risk: clearing keyword can search stale state.** `frontend/src/components/resource-filter-toolbar.tsx:130` calls `onChange(nextValue)` and immediately `onClearSearch()` from the same render. `frontend/src/components/resource-cluster-namespace-filters.tsx:118` similarly schedules the already-captured `onSearch` closure after a state update. React batching does not replace that callback's closed-over keyword. Change search APIs to accept the next keyword explicitly or apply filtering from committed state. Verify that clearing a nonempty query sends an empty keyword and returns all matching scope resources. Current callers with keyword search disabled are unaffected; test each enabled consumer rather than claiming a universal reproduction.

6. **P2 / browser validation required: shared form spacing removes margins without establishing a layout.** `frontend/src/app/ops-layout-consistency.css:53` sets `gap` on forms, while line 59 removes all form-item bottom margins within shared shells. This file does not establish grid/flex display for those forms. Ordinary block-form children do not consume gap, so affected forms can become vertically crowded. Confirm computed display and item separation on AI configuration, data-source configuration, and create-resource dialogs. Scope a grid layout to supported form structures or use adjacent-item spacing; avoid changing nested horizontal/inline forms globally.

7. **P2 / browser validation required: row-height guarantee is a minimum, not a content contract.** `frontend/src/app/globals.css:16115` assigns table-cell height/min-height and zero vertical padding; line 16128 assigns another minimum to the cell wrapper. HTML table rows expand for unbounded content. These declarations alone cannot enforce equal rows when labels, helper text, or custom renderers exceed 52px. Verify narrow resized name/label columns with multiline values and compare every visible row height. Bound each common cell renderer, expose full content through detail/tooltip, and keep measuring and expanded rows excluded. Do not fix by clipping interactive controls indiscriminately.

8. **P2 / browser validation required: reduced-motion coverage is scattered and structural.** `frontend/src/app/globals.css:15000` reduces animations inside selected Ops containers; other blocks at lines 791, 1145, 7634, 12349, 13281 and 13755 target distinct effects. These do not establish a single motion-token override for shell menus and body-portaled popovers/dialogs. Inspect Ant Design generated motion styles and actual portal transitions with reduced motion enabled. Establish a theme/provider motion policy and zero-duration semantic tokens for that preference; test submenu expansion, dropdown, drawer, modal, and route changes rather than relying on a regex contract.

## Cross-Cutting Integration Notes

- `frontend/src/app/layout.tsx:6` imports globals followed by multiple design, text, layout, solid-surface and topology stylesheets. Later solid-surface rules intentionally override older glass styling; hard-coded historical colors alone are not proof of a current dark-theme defect. Record computed styles in the browser before deleting overrides.
- Namespace filtering already uses the direct `NamespaceSelect` path in `frontend/src/components/resource-scope-filter-button.tsx:95`. Preserve this working path and verify alignment across network/storage/workload consumers instead of replacing it with a second popover.
- Column resizing already has pointer cleanup, keyboard handling and stored widths in `frontend/src/components/resource-table/resizable-header-cell.tsx`. Reuse it and test geometry, rather than creating another resize abstraction.
- This report does not establish UI coverage for all routes. Baseline screenshots should cover home, cluster overview, deployments, Pods, network Service, PVC/PV/SC, authorization, AI settings, and representative dialogs in both themes at 1440/1280/1024/390px.
