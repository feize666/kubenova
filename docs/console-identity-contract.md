# Console identity and authorization contract

Status: design gate only. Read-only source audit against `4a64294`; no migrations, identity-provider changes, Kubernetes writes, or identity implementation were performed. Paths below are repository-relative; line numbers refer to that commit. Runtime integration developed after this base must be reviewed separately.

## Decisions and blocking findings

Home authorization owns identity providers, Keycloak/OIDC configuration, MFA policy, users/groups, grants and revocations. Cluster authorization pages are inspection views of the same policy, filtered to the viewer's scope. Only a superadmin can grant/revoke access, change identities or policy, including through compatibility endpoints and generic Kubernetes YAML APIs. Preserve the existing local recovery administrator and local password login independently of Keycloak availability.

The present model cannot express namespace grants, groups, expiration, independent sensitive capabilities or session-wide revocation. Existing `RbacBinding` CRUD is a separate database inventory, not effective `ClusterRoleBinding` authorization and not Kubernetes reconciliation. Treating its current UI as a working grant editor would be misleading.

The highest-priority defect is `common/governance.ts:42`: `assertWritePermission` rejects only a missing role or literal `read-only`; `user`, unknown strings and operators pass. `users/users.service.ts:263,305` uses it to create/update users and accepts arbitrary role strings. An authenticated `user` can therefore reach a role-changing service path without a superadmin check. TypeScript role types do not validate database strings. This must be closed before enabling new identity users.

Shared cluster credentials make the API a privileged deputy. Cluster-only checks on dynamic APIs do not enforce namespace, Secret capability or RBAC administration. An operator can request writes to discovered authorization resources if the stored Kubernetes credential permits them. A viewer can request dynamic Secret details; `resources/resources.service.ts:1523` returns the Kubernetes object as `raw` without a sensitive-resource decision. Do not describe current read access as safe namespace-isolated access.

## Exact policy semantics

Four canonical roles: `superadmin`, `cluster-admin`, `operator`, `viewer`. `User.platformRole` is `superadmin` or `member`; scoped grant role is one of the other three. Return a computed display role if necessary; do not infer global privileges from the highest scoped role. Legacy `admin`/`platform-admin` mapping is a reviewed migration only, not a permanent string alias accepting new input.

| Action | superadmin | cluster-admin | operator | viewer |
| --- | --- | --- | --- | --- |
| Identity, grants, provider/MFA policy, global configuration | Manage | No mutation | No mutation | No mutation |
| Inspect effective grants | All | Only bindings intersecting own scope, redact other scopes | Own effective access | Own effective access |
| Ordinary resource metadata/read | All existing enabled scopes | Granted scopes | Granted scopes | Granted scopes |
| Ordinary namespaced workloads/config/network/storage writes | All, with security constraints | Granted scopes | Granted scopes | No |
| Logs / exec / Secrets / kubeconfig | Explicit audited use | Independent capability required | Independent capability required | Independent capability required; exec and Secret writes still require mutation role |

`cluster-admin` means scoped operations and authorization inspection, never grant/revoke, Kubernetes RBAC write, impersonation, `bind`/`escalate`, ServiceAccount token issuance, CSR approval, webhook/admission-policy modification or credential export of administrative identities. Reserve cluster-scoped mutations for superadmin. All non-superadmin sensitive capabilities default false. `logs` permits pod logs and authorized log-center queries; `exec` additionally requires operator or cluster-admin; `secrets` permits read, and writes additionally require a mutation role; `kubeconfig` permits generating an OIDC client configuration, not granting additional verbs. Base grants never imply these capabilities.

Policy signature: `authorize({userId, sessionId, clusterId, namespaceUid?, apiGroup, resource, subresource?, verb, name?, transport}) -> {allowed, policyVersion, matchingGrantIds, expiresAt, reasonCode}`. Callers cannot supply trusted roles, groups or grant IDs. Derive identity from a live session, groups from authoritative local membership and target from persisted object/discovery/parsed manifest. Missing identity/scope, unknown role/action, disabled user/cluster/group, expired session/grant/membership, revoked grant or unavailable authoritative policy store denies.

A valid grant has exactly one user or group, one explicit existing cluster and one or more explicit existing namespaces. No wildcard cluster/namespace, empty-means-all or future namespace inference. Capture Kubernetes namespace UID as well as name; deleted-and-recreated namespace requires a new grant. Cluster metadata viewing derives from any valid namespace grant; non-superadmin node/cluster-resource data uses a separate safe inspection allowlist and redaction, never arbitrary cluster-scope proxy access. Namespace creation/deletion belongs to superadmin.

At time `t`, require `validFrom <= t < expiresAt` (null expiry means no scheduled expiry), `state=active`, `revokedAt=null`, active membership/group if applicable and live namespace UID. Evaluate grants independently: an individual grant must authorize the complete action including sensitive capability; do not combine operator rights from one grant with exec on another viewer grant to manufacture exec permission. Union complete allowed decisions across grants. Revoking one grant does not negate another valid grant; global user/session revocation overrides every grant. Return remaining access in revocation previews.

Lists, totals, pagination, caches, exports, events and AI evidence must use the same permitted scope before aggregation. Never fetch all namespaces and rely on UI filtering. Resolve object IDs to actual scope before reading payload; never authorize only the user-supplied cluster query. Namespace aliases, YAML apiVersion/kind mismatch, multi-document YAML, Helm hooks, workload ServiceAccount selection and secret-volume mounts require validation. Independent Secret/exec restrictions also require admission controls against privileged pods, host access, privileged ServiceAccounts and workloads that expose secrets; RBAC alone cannot prevent workload-based escalation. This is a production gate, not a promise delivered by four capability booleans.

## Additive migrations, in order

All migrations first add nullable/defaulted columns or new tables. Keep legacy data for audit and rollback, but do not retain permissive authorization as a runtime fallback after cutover. Migrations run locally against fixtures first; this document authorizes no managed-cluster changes.

1. Add `User.platformRole` (`member` default), `authzVersion` (bigint, default 1), `recoveryAccount` (false), `localLoginEnabled` (true for existing local accounts). Inventory current admin aliases, active bindings and users before mapping. Mark the verified existing recovery account by immutable ID; retain its password hash and active status. Protect the last active recovery superadmin from deletion/demotion/disable in a serialized transaction. Do not rerun development seed to reset passwords or promote accounts. Unknown legacy roles receive no privileges and a migration issue, not automatic elevation.
2. Add `IdentityProvider(id, issuer UNIQUE, clientId, secretRef, enabled, configVersion, requiredAcr, createdAt, updatedAt)` and `ExternalIdentity(id, providerId FK, subject, userId FK, UNIQUE(providerId,subject))`; issuer is immutable after activation. Add `IdentityGroup(id, providerId FK nullable, externalId, name, active, version, UNIQUE(providerId,externalId))` and `GroupMembership(groupId FK,userId FK,state,validFrom,expiresAt,sourceVersion, UNIQUE(groupId,userId))`. Local and external groups have explicit authority; never accept groups from an unverified browser request.
3. Add `AccessGrant(id, userId FK nullable, groupId FK nullable, clusterId FK, role, state, validFrom, expiresAt nullable, revokedAt nullable, version default 1, createdByUserId FK, updatedByUserId FK, createdAt, updatedAt, legacyBindingId UNIQUE nullable)` plus `GrantNamespace(grantId FK, namespaceRecordId FK, namespaceName, namespaceUid, UNIQUE(grantId,namespaceUid))` and `GrantCapability(grantId FK, capability ENUM(logs,exec,secrets,kubeconfig), UNIQUE(grantId,capability))`. Add nullable `NamespaceRecord.kubernetesUid`. SQL checks enforce exactly one subject, canonical role/state and ordered expiry. 5. Add durable `AuthorizationChange(id, actorUserId, affectedUserId nullable, grantId nullable, version, reason, committedAt)` plus transactional outbox `AuthorizationOutbox(id, changeId FK, payload, publishedAt nullable, retryCount)` and `RbacReconciliation(clusterId,desiredVersion,observedVersion,status,lastError,updatedAt)`. Owner ID always comes from session, and current scope is rechecked before returning resource-linked content. Global channel templates remain separate superadmin administration.

Backfill grants as disabled migration candidates from `ClusterRoleBinding`: enumerate currently existing namespace UIDs, copy role/state provenance and give no sensitive capabilities automatically. Present exact differences to superadmin, activate explicitly, then switch policy behind a cutover flag. Historical cluster-wide access cannot be silently expanded to future namespaces. Do not translate `RbacBinding` inventory into privileges: it lacks cluster/roleRef. Shadow-evaluate prior to enforcement, record differences without returning unauthorized data, retain original rows for audit. Rollback may disable new identity features while preserving restrictive enforcement and recovery login; never roll back to permissive user mutation.

## API contract and ownership

New APIs use `/api/authorization`; home consumes them. Cluster views pass a cluster filter and the server constrains it. All writes require superadmin, fresh MFA (authTime within 5 minutes, configured assurance satisfied), reason, request ID and optimistic version (`If-Match`); stale version returns 409. Recovery sessions use an independently configured audited recovery path, not fake OIDC MFA claims. Validate DTOs with unknown fields rejected. Error codes: 401 session invalid; 404 nonexistent/inaccessible scope; 403 action/capability denied; 409 version/scope conflict; 503 authoritative policy unavailable. No errors leak secrets or existence outside scope.

| Method / endpoint | Request / response and authority |
| --- | --- |
| `GET /api/authorization/me` | Session subject only; effective clusters/namespaces, safe actions, capability decisions, policyVersion and earliest expiry. UI hint only; APIs reauthorize. |
| `GET /api/authorization/grants?clusterId=&cursor=` | Superadmin all; cluster-admin intersection only; other users own effective grants. No unrestricted directory/group membership exposure. |
| `POST /api/authorization/grants` | `{subject:{type:"user"|"group",id},clusterId,namespaces:[{name,uid}],role,capabilities:[],validFrom,expiresAt,reason}`; server returns grant/version, effective platform state and distinct reconciliation state. |
| `PATCH /api/authorization/grants/:id` | Full desired scope/role/capabilities/lifetime plus reason, If-Match; atomic version bump, audit, impacted-user epochs and outbox. Subject immutable; replace grant to change subject. |
| `POST /api/authorization/grants/:id/revoke` | `{reason}` plus If-Match; idempotent revoked state; returns change ID, platform enforcement status and Kubernetes reconciliation status. No hard delete. |
| `POST /api/authorization/users/:id/revoke-sessions` | `{reason}`; revoke all sessions, bump user epoch and close platform streams. Disabling user additionally blocks future login; return separate IdP logout status. |
| `POST /api/authorization/preview` | Superadmin proposed grant; complete decision diff, affected streams, remaining parallel grants and desired RBAC, no mutation. |
| `GET/POST/PATCH /api/authorization/providers[/:id]` | Superadmin; safe provider fields only; secrets written by secretRef, never returned. Connection check reports discovery/TLS/client readiness; no configuration auto-activation. |
| `GET/PUT /api/authorization/mfa-policy` | Superadmin policy administration; required assurance/roles/actions, step-up max age, recovery policy and observed Keycloak application status. |
| `POST /api/auth/oidc/:providerId/start`, `GET /api/auth/oidc/:providerId/callback` | Library-driven code flow with PKCE/state/nonce; bounded server transaction, exact registered callback and allowlisted return path. Issue local revocable session after validated identity and MFA. |
| `POST /api/auth/oidc/backchannel-logout` | Validate signed logout token with supported library, issuer/audience/events/jti replay protection; revoke linked sessions and streams. |
| `GET /api/auth/mfa`, `POST /api/auth/mfa/enroll`, `POST /api/auth/step-up` | Own enrollment/status only; enrollment redirects to trusted Keycloak account/required-action flow; success derived from newly verified assurance, not a UI toggle. |
| `GET /api/clusters/:id/kubeconfig/oidc` | Require kubeconfig capability and MFA, exact cluster enabled/readiness; return CA/server and approved exec-plugin OIDC configuration. No embedded access/refresh token, client secret or admin credential. |
| `GET /api/runtime/internal/sessions/:id/authorization` | Authenticated gateway only; fresh parent session/user/grant/target check; returns allow/deny, policyVersion, earliestExpiry, short lease. Does not return kubeconfig on every heartbeat. |
| `GET /api/notifications`, `POST /api/notifications/:id/read` | Recipient predicate uses session user ID; no client owner override; current scope check for linked resources. |

Existing users/security RBAC compatibility writes must call the same superadmin service or return a documented retired-endpoint error; aliases cannot retain weaker checks. Password resets, role changes, group changes, grant changes, disabled clusters and provider changes all emit authorization changes.

## Keycloak, MFA and recovery

Use a maintained standard OIDC client such as `openid-client`, with a version compatible with the server's Node/module runtime, pinned and tested. Use discovery/JWKS rotation, issuer/audience/signature/time validation, PKCE, state/nonce and exact redirects. Do not extend the custom runtime HMAC verifier into identity JWT validation. Authenticate by immutable `(issuer, sub)` only. Verified email is contact data; unverified email must never link an account. Even verified-email collisions require explicit authenticated linking by the owner plus superadmin policy, or provisioning to a separate pending identity.

Provider client roles/groups do not automatically confer platform superadmin. Group import uses stable IDs and authoritative reconciliation/events; removals invalidate membership and impacted user epochs. Handle missed events with scheduled reconciliation; unknown/stale membership denies group-derived access until refreshed according to a configured freshness window. A group change known only to Keycloak cannot be instantaneously known by this platform: require a trusted event/backchannel integration for prompt removal and expose reconciliation freshness.

MFA policy administration specifies who must step up and what verified assurance is acceptable. User enrollment is performed in Keycloak and does not itself prove the current platform session met MFA. Check supported `acr`/`amr` mappings and `auth_time` after authentication; reject absent/insufficient claims for protected actions. Keycloak outage must not remove local recovery login. Recovery account use is rate-limited, separately protected, durably audited and prominently visible to administrators; preserve existing hash and do not store its password in configuration exports or docs.

## Three independent enforcement planes

Platform: persist deny/revocation and affected user epochs atomically with audit/outbox. Every request authorizes from current state. Register every live SSE/WebSocket/exec/log stream by user, parent session, cluster, namespace and policy version; push revocation to all replicas, cancel upstream Kubernetes contexts and stop outbound frames. Recheck immediately before sensitive input and after bootstrap to close the handshake race. Timers enforce the earliest session/grant/token expiry. A short renewable lease (maximum 5 seconds) is a fail-closed fallback on lost events or policy-store failure, not the definition of immediate revocation.

For immediate platform revocation, acknowledgement must mean active gateway/HTTP replicas have applied the revocation barrier and closed affected streams; do not return `enforced` merely because the DB transaction committed. Use authenticated gateway registration, ordered change sequence, replayable outbox and per-instance acknowledgements. Return 202 with `enforcement:"pending"` when a replica is unreachable; its lease expires and it must reconcile before accepting new traffic. Single-process close lists are insufficient for multiple replicas. Distributed failure makes literal zero-delay global termination impossible; report actual enforcement status and the tested maximum fallback delay rather than promising instantaneous completion. Do not allow old browser access tokens to reopen a revoked parent session via a runtime ticket.

Kubernetes: reconcile grants to namespaced RoleBindings and explicit least-privilege roles using stable OIDC subject identity; use no wildcard verbs/resources and no built-in `cluster-admin` for scoped administrators. Record desired versus observed policy version; new kubectl access remains unavailable until readiness is verified. Revoke desired bindings immediately, retry idempotently, surface failure. Existing foreign RBAC can add rights because Kubernetes RBAC is additive; detect out-of-band bindings and block claims of exact enforcement while they exist. Namespace UID reuse must invalidate bindings before the recreated namespace can be used. Admission restrictions and dedicated low-privilege ServiceAccounts are required for safe workload writes.

Direct kubectl: VPN is a network prerequisite, not authorization. Require VPN-reachable API endpoint, configured OIDC issuer/audience, trusted CA and an approved exec credential plugin using authorization code + PKCE. Propose 5-minute maximum access tokens, no offline scope; refresh credentials stay only in the user's protected local credential store. Use per-user stable subject bindings, not a shared ServiceAccount and not stale token group claims as the sole grant source. Revoking refresh/login at Keycloak prevents renewal but cannot invalidate an already-issued offline-validated JWT before expiry. Removing all applicable Kubernetes RBAC denies subsequent requests after reconciliation; it does not reliably terminate already-established exec/log/watch connections. Immediate direct-stream termination would require an enforcing access proxy or network-session control and is outside native OIDC/RBAC guarantees. Do not conflate this limitation with the platform's own cancellable streams.

Disable new issuance through the old shared ServiceAccount export endpoint at cutover; inventory old exported credentials, remove owned bindings/ServiceAccounts through a separately reviewed rollout and respect token expiry. Merely hiding its button leaves the bypass intact. Do not delete unknown administrator access while reconciling owned objects.

## Ordered implementation slices and acceptance gates

1. **Minimum first slice: close user-management escalation and prove recovery.** Replace user/security RBAC mutation checks with a canonical explicit superadmin predicate across aliases; reject unknown role values; protect last recovery admin; add durable audit. Add tests proving `user`, `read-only`, operator, scoped cluster-admin and unknown strings cannot create/promote/reset/disable users or mutate grants; verified recovery admin can still log in. Introduce policy service adapter with explicit actions and default deny, without enabling OIDC or writing managed-cluster RBAC. This is the smallest safe implementable unit, not full namespace isolation.
2. **Additive state and complete HTTP boundaries.** Apply migrations 1-3 to disposable local DB; import disabled candidates; implement owner-filtered inspection and superadmin grant mutation; enforce namespace UID, capabilities, expiry and group state across matrix routes and aliases. Cover forged IDs, absent filters, legacy workloads/actions, Secret raw/YAML/revisions, dynamic RBAC, multi-object YAML and privilege-bearing workload specs. Gate non-superadmin rollout on complete route inventory; a handful of guarded screens is insufficient.
3. **Sessions and immediate platform streams.** Apply migration 4/outbox state, tie runtime tickets to parent sessions, validate immutable target tuple and current policy at bootstrap; implement all-replica stream registry/revocation acknowledgements/lease expiry. Test an already-open Go exec/log stream, Socket.IO and SSE through logout, disable, demotion, grant removal/expiry, group removal, race during bootstrap, missed event and control-plane loss. Assert upstream cancellation and no subsequent protected frames, not only HTTP 403 at connection time.
4. **OIDC/MFA and home authorization.** Add library and provider migrations, Keycloak discovery/PKCE/backchannel logout, no email auto-linking, session assurance and self enrollment. Home owns mutations; cluster admin view is read-only. Test bad issuer/audience/nonce, replay, disabled provider, stale group, missing MFA, IdP outage and local recovery. Never treat an enrollment-success callback alone as authorization.
5. **Kubernetes reconciliation and VPN kubectl.** Build desired manifests/plan first, review resource ownership and least-privilege/admission constraints, then test only on disposable cluster after separate deployment authorization. Verify `kubectl auth can-i` positive/negative scope/capability cases with actual OIDC users, namespace recreation, removed users, expired token, foreign RBAC detection and failed reconciliation. Disable shared exports and report direct-stream revocation limitations explicitly.
6. **Notifications and operational acceptance.** Add real recipient ownership if delivering inbox features; test cross-user access and grant removal. Exercise durable audit, recovery rotation procedure, outbox restart/replay, multiple gateways and observability of pending revocation/reconciliation. Publish measured enforcement behavior, not an identity-complete label, until every gate passes.
